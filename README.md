# 任务路由 · DSH 跨会话入口

这是一个可安装的 **DeepSeek Harness 组合包**。在 DSH 左侧栏打开「任务路由」，像发消息一样描述工作。它找的是**能接着做同一件事的会话**，不是「最近的会话」，也不是把一个项目的所有工作都塞到一个常驻线程里。

## 先试，不用安装

打开[离线演练](examples/try-router.html)，点「试跑：续接 A，同时新建 B」。也可以点「试跑：跨项目交接」，等上游结果出现，修改预览，只把你确认的内容交给下游。演练用的是同一套界面、规划器和状态机，但工作区、会话和回复都是虚构的；不联网，不操作文件，不用模型额度，刷新即重置。开发版不需要运行另一个 Web 服务器。

## 安装到实际 DSH

适配版本：**DSH 0.2.2-rc.5**（包括这个版本的桌面端）。宿主接口目前不是跨版本兼容层。版本不符时请勿强制豁免安装。

1. 在**你已登录的 DSH** 侧边栏进入 **插件 → 添加/安装插件**（选本地包），填入你克隆本项目的**绝对目录**（在项目根目录运行 `pwd` 即可取得）。

   也可以安装本地构建好的压缩包：同一安装框填入压缩包的**绝对路径**。安装的是当前 profile 的宿主和客户端插件，会向该 profile 生效；本项目的演练和测试不会自行做这步。不要用不同版本的全局 `dsh` 命令修改正在运行的桌面 profile。
2. 确认并启用 `dsh-router-agent`。按插件管理器提示刷新；**只有提示需要重启时**，先保存当前工作再重启 DSH。找不到「任务路由」时，可在插件列表查看该包和当前页面的启用/加载状态。没有开发 watcher 时，编辑源码不会自动更新安装包。
3. 在「任务路由 → 路由设置」中选择**已有**的通用工作目录，添加允许处理的项目目录和易识别的项目名。允许只配置通用目录。不会扫描子目录来扩大许可范围，也不替你创建项目文件夹。
4. 在「按任务选择模型」选择**自动**，选定一个 DSH 已配置的提供方，预览快速、标准、深度三档的实际模型和思考强度，再保存。也可以选**手动**指定三档。若只提供一个可用型号，同一型号可能按支持的思考强度区分，不会伪造三个模型。新会话的「标准模式 / PTC 模式 / 跟随 DSH 默认」单独设置；这不是模型强度。

卸载或暂停：在同一插件页关闭/移除此包。关闭入口不会撤销 DSH 已接受的任务，也不会删除已有执行会话。

### 从 0.1.3 更新（0.1.4 / 0.1.5）

- **带链接的投递类任务。** 「帮我投递 <链接>」「帮我申请/报名/填写…」现在会被当作可执行工作：只在一个项目做过同类工作时直接落到该项目，不再要求先说明要做什么。链接是独立的投递对象：**同一个链接**再次提交会续接原会话，**不同链接**照常在该项目新建，不会混进上一份投递。
- 已有状态为「待选择」的分项，刷新页面后点 **「重新匹配此项（不发送）」** 即可按新规则重算，确认后才会发送。

### 从 0.1.2 更新到 0.1.3

- **免重复选项目。** 唯一获准的工作项目、明确的项目标记或唯一同一事项的会话可以直接确定目录。通用写作/问答走通用目录。多个项目时，可在设置里一次性选择「未指名项目时的默认项目」用于没有其他线索的独立工作；不会盖过明确提到的项目，也不会替你在多个相似会话中猜一个。
- **按实际工作选执行模型。** 轻量修订、常规实现、系统性分析分别按快速、标准、深度处理；可显式要求档位。旧版三档完全相同（含思考强度）时默认转用自动策略，只在已选提供方的真实目录内映射。之前已配成不同档位的保留手选；也可显式手动固定三档相同。结果卡区分创建计划与宿主确认的模型。复用时不更换模型。
- **更新前已经在等你选项目的独立分项**可以点「重新匹配此项（不发送）」。核对推荐后再点「使用此会话」或「在此新建」。这不会重提整条请求；已执行的任务不会因此重发或合并。
- **不必说“继续”。** 入口用本地已接纳分项的原始任务和实时会话目录作为匹配线索，不依赖会话标题已更新。即便原会话正忙，只要能证明同一项工作、同一目录也可排队。主题相近但目标、对象、日期或工单冲突时，不因“上次刚用”而复用；明确要求另开会话也不会被忽略。
- **新建模式独立。** 旧版未传 `agentPreset`，继承了 DSH 当前选中的预设；若当前选的是 PTC，新开也为 PTC。0.1.3 路由新建默认明确用**标准模式**，可在设置里选 **PTC 模式** 或 **跟随 DSH 默认**。不改 DSH 全局预设和已有会话，也不会把升级前已发出的创建键改成不同预设。

### 从 0.1.1 更新到 0.1.2

如果旧分项显示 **The router could not confirm a newly created persistent session**，不要重发整单。DSH 桌面可在新会话写入三条权限设置和一条子代理选模策略；这四条都是初始化，不代表开始执行。0.1.2 识别这组记录；任何工作消息、排队记录、未知事件或重复策略仍不能算空白。

刷新 DSH 页面，打开原失败分项的 **预览空会话恢复**。核对目标目录及会话 ID 后点 **确认恢复并仅投递此项**。入口只核验这个持久空会话并沿用其当前模型，不另建、不更改模型，不自动恢复其他失败项。已归档、有工作记录或身份不符时会停止。如果宿主明确证明会话不存在，可按界面提示以同一创建键重试；不需要清除浏览器记录。如果同一需求曾被手动提交多次，**只确认你要执行的那一项**。

### 从 0.1.0 更新到 0.1.1

0.1.1 修复了新建会话时出现的 `cannot get property "remote.routerAgent" without inject`。更新后刷新 DSH 页面，再打开「任务路由」。在原来的失败分项点 **重试此项**，不必重新发送整条任务。版本更新不会重置已有的目录、模型设置或任务日志；已投递的其他分项不会因重试本项而重发。

## 预期行为

| 你发的内容 / 情况 | 实际行为 |
| --- | --- |
| 「继续 A 项目昨天的发版检查；另外给 B 项目做一份新的导出验收清单。」 | 若 A 有一个明确的发版检查会话，续接 A；B 是新任务，在 B 新建。两者各自显示进度、结果和去向。 |
| 同一个项目有两段对话都像，或者看不出项目 | 只提示你选择这一项。可预览候选、选择已有会话，或明确选目录新建。其他独立且明确的项不等它。 |
| 「先在 A 设计新格式，然后根据上一步结果在 B 更新导入文档。」 | A 先走。A 有可归属的结果后，B 显示**整段待发送的正文**。你可删改；不点「批准并发送交接」就不向 B 投递。失败、需审批或结果归属不明，都不会放行下游。 |
| 「用深度档，在 B 项目另开会话排查性能瓶颈。」 | 新建时按显式要求选档。其他新任务按复杂度选档。**续投永不改模型；新建选模也不改 DSH 的全局默认模型。** |
| 命中的会话正在忙 / 对某一项追问 | 忙时排队，不打断、不另起。该项下的追问始终绑定该会话；不会把「改第二条」猜成另一项的工作。 |

## 安全边界与持久性

- **只服务本人的 DSH 会话。** 客户端使用当前已鉴权的 DSH Remote；宿主的创建、局部选模和轻量分类端点均检查真实 owner 身份。没有外部服务，没有单独监听端口，不修改应用安装目录。仍沿用执行会话自己的权限和审批规则，入口不代批。
- **先元数据后摘录。** 候选只包括许可的精确目录、未归档的普通可续聊会话。排除子代理、未使用的空会话、需要迁移或无法证实目录的会话；原生列表仍标空白但能精确核实已投递请求的会话可以续接；工作目录发生漂移不会跟着投递。仅在需要时获取少数候选的近期用户文本。路由分类使用快速档、禁用工具，有输入/输出预算；只给分类器本次任务、少量候选标题、匿名项目线索和必要的短摘录，不附整段历史。本地已投递任务的原句只在当前入口匹配，不直接转给分类器。所选模型提供方依然会收到参与分类的这些文本。模型不可用或返回无效内容时降级到保守规则，理由显示在分项中。
- **状态不靠猜。** 每项用固定的创建键、投递请求号和投前游标。只有在连续事件中能把该输入、对应轮次、最终文本和成功结束关联起来才显示「已完成」。成功入队不是执行成功；超出核对窗口、同轮混入其他人工输入或无可归属文本时显示「状态未知」。这时优先查看原会话或刷新，不要当成失败重复新建。
- **任务记录在当前浏览器的这个 DSH 站点内保存。** 使用本地存储和 Web Locks 防止多个标签页重复投递；不跨设备、浏览器配置或站点地址同步。任务和结果可能含敏感内容，本机浏览器存储不是加密保险箱。不要在仍有任务时清空站点数据。页面关闭后，已入队的工作由 DSH 继续执行；入口下次打开会重新核对状态，**没有后台守护进程替你确认交接**。
- **首版有意保守。** 中文命令的显式并列、顺序和引用最可靠；复杂条件、模糊指代、矛盾依赖需重述或手动选择。不能用本入口把归档会话、外部 Codex/Claude Code 会话或别人的会话当作执行目标。长期离线或超长轮次可能必须打开原会话核对。

## 开发与验证

Node 22+；运行时使用宿主提供的 DSH 库，唯一的构建依赖是 esbuild。仓库内带有可加载的客户端产物和单文件演练。

```sh
npm ci
npm run check                 # 重建客户端/演练，随后运行 Node 自动测试
node scripts/verify-package.mjs  # macOS：用真实桌面 CLI 在临时 DSH_HOME 组合 Web 配置，未启动 Web 服务
sh scripts/dsh-runtime-smoke/run.sh  # macOS：在禁网沙箱运行真实 Cordis/Typert、会话引擎、JSONL + 合成模型
npm pack                      # 打出可安装的 .tgz
```

其他安装位置可把匹配版本的 DSH CLI 绝对路径传给配置验证脚本。测试仅在隔离环境内使用虚构的任务或合成模型，不借用正常用户的会话作为测试目标。[真实宿主烟测及覆盖边界](scripts/dsh-runtime-smoke/README.md)包含仅 owner 可用、忙时排队、重复请求无第二轮、错误请求号不取旧结果、会话选模不改全局、归档后拒投等检查。

### 代码入口

- [DSH 模块与侧栏面板](src/client.mjs)：官方模块工厂、owner 门禁、挂载及刷新回收。
- [宿主半侧](src/host/index.mjs)／[共享 RPC 合同](src/host/contract.mjs)：无工具推理、安全新建和仅本会话的选模。

- [状态机](src/core/controller.mjs)／[投递日志](src/core/journal.mjs)：同一请求的幂等投递、依赖门禁和恢复。
- [DSH 适配器](src/dsh/adapter.mjs)／[结果归属](src/dsh/observation.mjs)：宿主协议、许可边界与按请求核对轮次。
- [入口组件](src/ui/main.mjs)：配置、总任务与分项视图。
